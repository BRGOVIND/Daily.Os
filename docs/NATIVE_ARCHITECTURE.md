# Native Architecture

Phase 7 extends Daily OS **beyond the browser** with a Tauri 2 desktop shell.
The web app is unchanged and remains the source of truth; the shell *wraps* it
and adds native superpowers — a system tray, global shortcuts, a floating Quick
Capture window and OS notifications. No backend, no network, no account: the app
still does everything locally in the WebView's storage.

```
┌─────────────────────────── Tauri (Rust) ───────────────────────────┐
│  window-state · single-instance · tray · global-shortcut           │
│  notification · fs · dialog · opener · autostart                    │
│                    ▲  emit "native:action"      │ #[command] IPC    │
│                    │                             ▼                   │
│  ┌──────────────── WebView (same origin) ─────────────────────────┐ │
│  │  main window  →  the existing Next.js app (static export)      │ │
│  │  quick-capture window  →  /capture route (always on top)       │ │
│  │  window.__TAURI__  ◀── dependency-free bridge (src/lib/native) │ │
│  └───────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────┘
                         IndexedDB (shared by both windows)
```

## Why this design

- **Wrap, don't rewrite.** The frontend is untouched. `next.config.mjs` switches
  to a static export (`output: 'export'` → `./out`) **only** when the Tauri CLI
  runs the build (it sets `TAURI_ENV_*`); `next dev` / `next build` for the web
  are unaffected.
- **Web build gains zero dependencies.** The frontend talks to the shell through
  the `window.__TAURI__` global (`withGlobalTauri: true`), wrapped by a tiny
  bridge in `src/lib/native/`. Nothing imports `@tauri-apps/*`, so the browser
  bundle and its `tsc`/`lint`/`build` are identical to before. Every native
  function is a **no-op off-shell**, guarded by `isTauri()`.
- **One write path.** Quick Capture and the main window are two WebViews on the
  same origin, so they share IndexedDB. Quick Capture uses the exact same
  `commitTask` helper; Dexie's live queries update the main window instantly.

## Folder structure

```
src-tauri/
  Cargo.toml            # Rust crate + Tauri 2 plugins
  build.rs              # tauri-build codegen
  tauri.conf.json       # window, tray, security (CSP), bundle, plugins
  capabilities/
    default.json        # least-privilege permission set per window
  src/
    main.rs             # thin binary entry (calls the lib)
    lib.rs              # plugins, setup, IPC commands, global shortcuts, quick capture
    tray.rs             # system tray icon + menu
  icons/                # generated by `tauri icon` (git-ignored)

src/lib/native/         # frontend bridge (web-safe)
  bridge.ts             # isTauri / invoke / listen via window.__TAURI__
  native.ts             # high-level API (windows, fs, autostart, notifications)
src/hooks/useNativeActions.ts   # routes tray/shortcut actions into the app
src/app/capture/page.tsx        # the Quick Capture window's route
src/components/layout/NativeSection.tsx  # the Desktop settings pane
```

## IPC overview

Two directions, both explicit and typed:

**Rust → JS** — a single event, `native:action`, with a string payload the
frontend routes (`useNativeActions`):

| Payload | Triggered by | Frontend does |
| --- | --- | --- |
| `open` | tray "Open" | focus (window already shown by Rust) |
| `dashboard` | tray / `Ctrl+Shift+D` | open today's workspace |
| `quick-add` | tray "Quick Add" | open the task composer |
| `focus` | tray / `Ctrl+Shift+F` | enter Focus Mode (today) |

`Ctrl+Shift+Space` opens the Quick Capture window directly in Rust (fastest path)
rather than round-tripping through the frontend.

**JS → Rust** — `#[tauri::command]` handlers (`invoke(...)`):

| Command | Purpose |
| --- | --- |
| `show_main_window` | restore + focus the main window |
| `open_quick_capture` | show/create the floating capture window (reused for <100 ms) |
| `close_self` | close the calling window (Quick Capture on save/Esc) |
| `enter_focus_mode` | surface main + emit `focus` |
| `reveal_path` | reveal a folder/file in the OS file manager |
| `backup_dir` | ensure & return `<app data>/backups` |
| `set_autostart` / `is_autostart` | launch-at-login toggle & state |

Notifications reuse the notification plugin's own commands
(`plugin:notification|notify` etc.) invoked from `native.ts`.

## Security model

- **Least privilege.** `capabilities/default.json` grants only the specific
  plugin commands used, scoped to the `main` and `quick-capture` windows. File
  access is confined to `$APPDATA/backups`.
- **Strict CSP** (`tauri.conf.json`): `default-src 'self'`, no remote scripts,
  no `connect-src` beyond the Tauri IPC channel — matching the app's offline,
  no-network guarantee.
- **No arbitrary shell/exec.** The shell exposes only the narrow command set
  above; there is no generic command execution or open-any-path primitive.
- **Single instance.** A second launch focuses the existing window instead of
  spawning a duplicate.
- **Updater is prepared but off.** `createUpdaterArtifacts` and the updater
  plugin are disabled until signing keys exist; the `updater` Cargo feature is a
  placeholder.

## Building the desktop app

Requires the Rust toolchain and the Tauri CLI (a native dev machine — not part of
the web CI):

```bash
npm install                         # pulls @tauri-apps/cli
npx tauri icon public/icon-512.png  # once: generate app/tray icons
npm run dev:desktop                 # dev: loads http://localhost:3000
npm run build:desktop               # release: static-export + bundle installer
```

## Performance

- **Quick Capture < 100 ms** — the window is created once and *reused* (shown +
  focused) on subsequent invocations.
- **Small native footprint** — release profile uses `lto`, `opt-level = "s"`,
  `strip`, `panic = "abort"`, `codegen-units = 1`.
- **Web unchanged** — same code-split bundles; the shell adds a thin Rust host,
  not a second frontend.

## Future mobile architecture

Tauri 2 shares one Rust core across desktop and mobile. The desktop-only plugins
(single-instance, autostart, global-shortcut) are already gated behind
`#[cfg(desktop)]` / a `cfg(not(mobile))` dependency target, and `run()` carries
the `#[cfg_attr(mobile, tauri::mobile_entry_point)]` hook — so an
`android`/`ios` target can be added later (`tauri android init`) that reuses the
same frontend, IPC commands and tray-less action routing without touching the
web app.
